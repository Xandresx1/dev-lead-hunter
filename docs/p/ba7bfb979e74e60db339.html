Nasdaq Futures Auto Trader I need a fully automated system that will execute my already-proven Nasdaq futures strategy through Interactive Brokers. The strategy itself is fixed; what I’m missing is the reliable “glue” that listens for my trade instructions and places, manages, and tracks the orders from start to finish without manual intervention. Signal intake • Buy and sell messages arrive to me as plain-text alerts sent simultaneously by SMS and posted in a private Discord channel. Your program should monitor both sources in real time, parse the ticker, side, size, stop-loss and target parameters embedded in each message, and translate them into Interactive Brokers API orders within a few seconds of receipt. Core responsibilities • Submit market or limit entries (as specified in the alert), attach bracket exits, and adjust any stops or targets that the alerts later update. • Keep an internal log of every action—timestamp, raw alert text, order ID, fill status, and any API error—for quick auditing. • Pause trading automatically if connection to Discord, SMS gateway, or IB breaks, and send me a notification so I can investigate. • Allow me to toggle the system on or off with a simple command or small UI, but require no other daily maintenance. Deliverables 1. Source code and compiled executable or script ready to run on Windows 10/11. 2. A brief setup guide: how to install dependencies, link the IB Gateway/TWS, connect to the SMS and Discord feeds, and start/stop the program. 3. One live demonstration (screen-share is fine) showing an alert flowing through to a filled order and the log capture. Acceptance criteria • Average round-trip from alert arrival to IB order submission ≤ 3 seconds. • All order details (price, quantity, stop, target) match the original alert exactly. • System remains stable during a full trading session (RTH and ETH) with at least five simulated trades. Please build with whatever language or libraries you’re most comfortable using—Python and the official ib_insync wrapper are perfectly acceptable, but I’m open to other solid approaches as long as they meet the requirements above.
