Build Employee Training Portal Job brief – Employee information and training portal We need an experienced full-stack developer to build and deploy a modern web portal where each of our about 80 employees has a personal page. Employees get project information, guides and short training tasks there, and confirm when they have completed them. Admins push content to groups and see who has completed what. We want a working first version within 1–4 days. Overview We are a Norwegian organisation with about 80 employees, rolling out a new internal IT system. We want employees to feel informed and confident, and we want to know who has completed the training. • Users: about 80 employees and 2–5 admins. Expect a few hundred tasks and documents in the first year. • Language: the user interface must be in Norwegian (Bokmål). We will supply or review the texts. All interface strings must sit in one translation file. • Look and feel: modern, clean and friendly, on desktop and mobile. It should feel like a nice product, not an intranet. See the attached example screens. • Our identity: we will tell the selected freelancer who we are. Until then, please treat this as an anonymous client. • Example screens: we have made mock-ups of the employee page and the admin tool. Use them as a guide for layout and features, not as a pixel-perfect design. Employee features Each employee has a personal page at a stable address, for example /kari-nordmann, that shows only what is meant for them. 1. Personal start page: greeting with name, a progress bar ("7 of 10 tasks completed"), the next tasks due, and the latest news. 2. News and information: short posts from admins with text, images, links and attachments. Newest first, with unread posts marked. 3. Guides and documents: a library of user guides (PDF, Word, links to videos), searchable and grouped by topic. 4. Tasks: items the employee must complete, of three kinds: ◦ Read and confirm: "I have read this" checkbox. ◦ Process walk-through: a numbered list of steps (text and screenshots) where each step can be ticked off, ending with "I have completed the walk-through". ◦ Quiz: a few multiple-choice questions, with a pass mark set by the admin and a retry option. 5. Feedback: on every task, the employee can rate it (for example 1–5 or thumbs up and down) and write a comment or question. 6. Due dates and status: each task shows not started, in progress, completed or overdue. 7. Account: change password and log out. Admin features Admins must be able to run everything without a developer. Publishing to a group of employees must take a minute or two. 1. Employees: import from CSV (name, work email, department), add, edit and deactivate. Send invitation emails. 2. Groups: create groups (for example departments or project roles).
